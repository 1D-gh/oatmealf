# oatmealf 0.1.13

- Layouts that were not loaded in the editor are reported separately instead of being
  labeled `REVIEW NEEDED`.
- Plugin names are identified from matching declarations in the supplied engine source
  when possible.

# oatmealf 0.1.12

- Run captures are now saved under `exports` instead of `evidence`.
- Generated reports use shorter wording and avoid possessive phrases.

# oatmealf 0.1.11

- The console now announces each stage while a run is working: memory scans, layout
  capture, verification, comparison, source indexing, placeholder binding and output.
- Long stages show live progress when the console is interactive. Memory scans report a
  percentage, source-tree passes report file counts, and redirected output stays quiet.
  Progress goes to the error stream, so piped standard output is unchanged.
- Running the tool with no options while no game or editor is running now prints the
  option summary under the error instead of the error alone.
- `--game-dump` and `--editor-dump` are renamed to `--game-layouts` and
  `--editor-layouts`, matching the `game-layouts.json` and `editor-layouts.json` files
  they read. The old option names remain accepted as aliases, and messages that said
  "dump" now say "capture".
- Missing explicitly named processes now recommend the current `--game-layouts` or
  `--editor-layouts` option instead of the hidden legacy option name.
- The planner source file is split into `planner/` modules (core planning, placeholder
  bindings, tests) with no behavior change.

# oatmealf 0.1.10

- Automatic placeholder bindings now use scope-aware C++ function and brace parsing.
  Assignments are only emitted in matching fill functions, after the last unconditional
  sibling assignment, and each generated binding site is deduplicated.
- Buck's captured layouts now produce complete source copies with placeholder assignments
  for every recoverable resource member. The generated engine completed a full editor build,
  opened cooked materials, meshes and a level without shader or uniform-buffer failures, and
  matched all 153 live game layouts.

# oatmealf 0.1.9

- Generated resource members are now bound to engine placeholder resources automatically.
  The tool finds the renderer functions that already fill several sibling members of the
  same struct, clones a same-typed sibling's fallback expression (or uses a fixed table of
  engine globals such as `GBlackVolumeTexture`), and inserts the assignments there in the
  generated source copies. Bindings are listed in the report; members that cannot be bound
  confidently keep a review note instead of being guessed.

# oatmealf 0.1.8

- Trailing member insertions in structs that expand a shared parameter table are appended
  inside the consumer's own declaration block instead of stopping at review. The append
  reproduces that consumer's captured member sequence exactly and leaves every other table
  consumer untouched, so layouts like InstancedView are reconstructed with their captured
  member names.

# oatmealf 0.1.7

- Constant-buffer growth is only modeled as trailing placeholder padding when every editor
  member keeps its captured offset and shape in the game layout. Mid-struct insertions and
  reshapes now go through member-level source edits or `REVIEW NEEDED` instead of producing
  a padding candidate that binds but writes moved members at their old offsets.
- Placeholder members generated by the earlier ShaderDriftCheck releases are recognized as
  placeholders again, so previously patched editors keep modeling instead of stopping at
  review.
- Metadata hashing rejects evidence whose nested definitions expand past a fixed
  serialization budget instead of consuming unbounded memory and time.

# oatmealf 0.1.6

- Evidence captured by the earlier ShaderDriftCheck build can be read again.
- The same capture can no longer be used as both the game and editor input.
- Obvious game/editor capture swaps are rejected with a clear error.
- Malformed nested-array metadata now stops safely instead of expanding without a limit.
- Failed runs no longer leave an empty output directory behind.
- Ctrl+C during source planning now exits with code 130 instead of producing a partial review result.
- The opt-in live-capture test now works with a custom Cargo target directory.

# oatmealf 0.1.5

- Saved-capture runs without `--engine-root` now explain that the evidence cannot identify an engine source tree, print the rerun command and exit successfully without creating output.

# oatmealf 0.1.4

Changes since ShaderDriftCheck 0.1.0:

- Renamed the tool, executable, reports and generated placeholder fields to `oatmealf`.
- Improved source generation for layouts that share nested structs or Unreal parameter tables.
- Added source lookup under `Engine/Plugins` for uniform buffers defined by engine plugins.
- Source fallback lookup now builds one parallel declaration index instead of scanning the engine tree again for every missing struct.
- Missing engine source now prints instructions for `--engine-root` and exits cleanly before capture or output generation.
- `--engine-root` now accepts the Unreal root, `Engine` or `Engine/Source` directory.
- `-o, --output` now selects an output parent. Each run creates a timestamped directory inside it without touching existing files.
- Completed runs now exit successfully when the report contains `REVIEW NEEDED`. Exit code 2 is reserved for capture, input or tool errors.
- Reports now distinguish the game hash, current editor hash and generated source hash instead of showing the internal `modeled exact` status.
- Missing editor layouts are reported as unavailable instead of displaying a zero hash.

Against Buck's 153-game/151-editor capture, the new planner verifies 22 of 24 changed layouts and generates four source files. The remaining `WaterVF` and `WaterRaytracingVF` layouts are not present in that editor capture because its Water plugin was not loaded.
